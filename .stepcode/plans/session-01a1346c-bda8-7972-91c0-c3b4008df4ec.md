# 为 Sleipnir 增加远程 SSH 连接能力

## 1. 目标与非目标

### 目标
- 新增「连接远程主机」入口（命令面板 / 菜单 / `⌘⇧H`），打开一个浮层列出可连接的 SSH 主机。
- 主机来源双轨：**解析 `~/.ssh/config`**（只读）+ **应用内设置 `ssh.hosts`**（可编辑 JSON）。
- 连接方式：在新标签/分屏里以**子进程**方式运行 `ssh`，完全复用现有 PTY 管道（`TermView::new_local_with` 的 `Shell::WithArguments` 接缝）。
- 口令 / 密钥口令短语通过 **SSH_ASKPASS 助手**在 Sleipnir 自己的模态框里输入，不回显、不落盘。
- 设置项、文档（settings.md / example json / README / CHANGELOG）、中英文案、单元测试齐备。

### 非目标（明确不做）
- 不自实现 SSH 传输层 / channel / 加密（不做 russh 式原生客户端）。
- 不做 SFTP / 端口转发管理 UI / 密钥生成 / known_hosts 管理（这些都交给 `ssh` 本身，用户在终端里照常用）。
- 不做远程 OSC 133 shell integration（远端 shell 没有注入脚本，Run Ledger 对远程会话不跟踪命令——文档说明）。
- 不做主机编辑表单 UI（第一阶段主机通过 `settings.json` 维护；表单编辑器列为可选后续）。

## 2. 总体架构

```
┌────────────────────────── crate: sleipnir_ssh (新增，纯逻辑，无 GPUI) ──────────────────────────┐

│ askpass.rs      AskpassMessage 协议 + askpass 客户端(供主程序子命令) + askpass 脚本生成            │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
                 ▲                                    ▲
                 │ 消费                                │ 依赖
┌────────────────┴──────────────┐        ┌────────────┴───────────────┐
│ sleipnir_settings (ssh 段)     │        │ sleipnir (主程序)           │
│  SshSettings / SshHostSettings │        │  main.rs: `ssh-askpass` 子命令│
└───────────────────────────────┘        └────────────────────────────┘
                 ▲
                 │ 读取
┌────────────────┴──────────────────────────────────────────────────────┐
│ sleipnir_ui                                                            │
│  src/ssh/mod.rs      连接计划 SshConnectPlan（program/argv/title/env）   │
│  src/ssh/askpass.rs  AskpassServer（Unix socket 监听，每连接一问一答）    │
│  TermView::new_ssh   持有 SshSession，转发 Askpass 事件给 AppShell        │
│  app_shell/ssh_hosts.rs  连接浮层（过滤 + 列表 + 键盘导航）                │
│  app_shell 的 SshPromptState  口令模态框（掩码输入）                      │
└───────────────────────────────────────────────────────────────────────┘
```

### 一次连接的完整数据流

1. `⌘⇧H` / 面板 / 菜单 → `AppShell::open_ssh_hosts(cx)`：`resolve_hosts(settings)` 合并两路主机，写入 `AppShell.ssh_hosts`，`set_input(Overlay(SshHosts))`。
2. 浮层内输入过滤，`↑↓` 选择，`Enter` → `AppShell::connect_ssh_host(idx, window, cx)`。
3. 生成 `SshConnectPlan { program: settings.ssh.program, argv: build_ssh_argv(host), title: Some(alias), env: {...} }`，走 `spawn_term_view_ssh` → `TermView::new_ssh(...)`。
4. `TermView::new_ssh`（unix 且 `ssh.askpass != false`）：
   - `AskpassServer::bind()` → `~/.config/sleipnir/ssh-askpass/<hex>.sock`（目录 0700，socket 0600）；
   - `ensure_askpass_script()` 生成 `~/.config/sleipnir/ssh/askpass`（0700，内容为 `exec "<current_exe>" ssh-askpass "$@"`，仅在内容变化时重写）；
   - `env` 注入 `SSH_ASKPASS`、`SSH_ASKPASS_REQUIRE=force`、`SLEIPNIR_SSH_ASKPASS_SOCK`；
   - 清掉继承来的集成标记（`ITERM_SESSION_ID`/`GHOSTTY_RESOURCES_DIR`/`KITTY_SHELL_INTEGRATION`/`WEZTERM_EXECUTABLE`/`SLEIPNIR_OSC133_LOADED` 置空），避免远端 shell 误判；
   - `Shell::WithArguments { program: "ssh", args, title_override: Some(alias) }` → 现有 `TerminalBuilder` → PTY。
5. ssh 需要口令 → 执行 askpass 脚本 → `sleipnir ssh-askpass "<prompt>"` → 连接 socket → 发 `AskpassMessage::Request`。
6. `AskpassServer` 的 OS 线程把请求经 `async_channel` 交给 GPUI 任务 → `TermViewEvent::Askpass { prompt, reply }` → `AppShell` 置 `InputMode::SshPrompt(SshPromptState)`，渲染掩码输入框。
7. 用户回车 → `reply.send(Some(secret))` → socket 回写 `AskpassMessage::Secret` → 助手打印到 stdout → ssh 继续。`Esc` → `Cancel` → 助手 exit 1 → ssh 回落到 TTY 交互或报错。

## 3. 新增 crate：`crates/sleipnir_ssh`

包名 `sleipnir_ssh`，workspace 成员 + `[workspace.dependencies]` 条目。依赖：`serde`、`serde_json`、`anyhow`、`log`；dev：`tempfile`。**不依赖 gpui**，保证可单测。

### 3.1 `src/ssh_config.rs` — `~/.ssh/config` 解析
- `pub struct SshConfigHost { alias, hostname: Option<String>, user: Option<String>, port: Option<u16>, identity_files: Vec<String>, proxy_jump: Option<String> }`
- `pub fn parse_ssh_config(text: &str) -> Vec<SshConfigHost>`
  - 行首 `#`/空行跳过；支持 `Key Value` 与 `Key=Value` 两种写法；大小写不敏感的关键字。
  - 只收集顶层 `Host` 块；进入 `Match` 块后停止收集直到下一个 `Host`（保守：不猜 Match 条件）。
  - 一个 `Host` 行可跟多个模式：含 `*`/`?`/`!` 的模式**跳过**（不作为可选项）；纯别名才收录。
  - `Include`（glob，支持 `~`）递归加载，深度上限 8 + 已访问集合防环。
  - `HostName`/`User`/`Port`/`IdentityFile`/`ProxyJump`/`ProxyCommand` 识别；`Port` 非数字则忽略该字段。
- `pub fn load_ssh_config(path: &Path) -> Vec<SshConfigHost>`：读文件失败返回空并 `log::warn!`（不阻塞 UI）。
- `pub fn default_ssh_config_path() -> PathBuf`：`~/.ssh/config`。

### 3.2 `src/lib.rs` — 主机模型与合并
- `pub enum HostSource { SshConfig, App }`
- `pub struct SshHostEntry { alias, hostname, user: Option<String>, port: Option<u16>, identity_file: Option<String>, proxy_jump: Option<String>, extra_args: Vec<String>, source: HostSource }`
  - `impl SshHostEntry { pub fn display(&self) -> String /* user@hostname[:port] */, pub fn argv(&self) -> Vec<String> }`
- `pub fn resolve_hosts(config_hosts: &[SshConfigHost], app_hosts: &[AppHost], read_config: bool) -> Vec<SshHostEntry>`
  - 应用内主机在前（用户 curated），按 alias 排序；`ssh_config` 来源随后，按 alias 排序；
  - **同名 alias 去重，应用内优先**（用户显式配置覆盖 ssh config）。
- `pub fn build_ssh_argv(entry: &SshHostEntry) -> Vec<String>`
  - 选项一律放在目标之前：`["-p", port] ["-l", user] ["-i", id] ["-J", jump] [extra_args...] [user@]hostname`
  - 目标**永远是最后一个参数**，保证 `extra_args` 不会被当成远端命令执行（安全要点，单测固定）。
  - `SshConfig` 来源：argv = `[alias]`（让 `ssh` 自己读配置，自动获得 ProxyJump/IdentityFile 等全部语义），仅在 alias 需要转义时不特殊处理（argv 直传，无 shell）。
- `pub fn filter_hosts(hosts, query) -> Vec<usize>`：大小写不敏感子序列匹配（复用命令面板同款打分思路：alias 前缀 > alias 子序列 > display 包含）。

### 3.3 `src/askpass.rs` — 协议 / 客户端 / 脚本
- `pub enum AskpassMessage { Request { prompt: String }, Secret { value: String }, Cancel }`，`#[serde(tag="kind", rename_all="snake_case")]`，NDJSON 一行一条。
- `pub fn askpass_socket_dir() -> PathBuf` = `sleipnir_settings::config_dir()/ssh-askpass`（注：`sleipnir_ssh` 依赖 `sleipnir_paths` 的 `config_dir()`，避免反向依赖 settings）。
- `pub fn askpass_script_path() -> PathBuf` = `config_dir()/ssh/askpass`。
- `pub fn ensure_askpass_script(exe: &Path) -> Result<PathBuf>`：写 `#!/bin/sh\nexec "<exe>" ssh-askpass "$@"\n`，`set_mode(0o700)`；已存在且内容一致则跳过。
- `pub fn run_askpass_client() -> i32`（供 `sleipnir ssh-askpass` 调用）：
  - 读 `SLEIPNIR_SSH_ASKPASS_SOCK`，prompt 取 `argv[1]`（缺失用默认串）；
  - `UnixStream::connect`（超时 10s）→ 写 `Request` 行 → 读一行（超时 10 min）；
  - `Secret` → 原样打印到 stdout（不带换行结尾由 ssh 处理，实际打印 value 后换行）+ exit 0；`Cancel`/超时/任何错误 → exit 1。
- 全部 socket 代码 `#[cfg(unix)]`；Windows 下 `run_askpass_client` 编译为 `unimplemented` 桩并 exit 2（不会被执行，因为 Windows 不设置 `SSH_ASKPASS`）。

## 4. 设置层（`crates/sleipnr_settings/src/lib.rs`）

```rust
#[serde(default)] pub struct SshSettings {
    pub program: Option<String>,        // 默认 "ssh"
    pub read_ssh_config: bool,          // 默认 true
    pub askpass: bool,                  // 默认 true（仅 unix 生效）
    pub hosts: Vec<SshHostSettings>,    // 默认空
}
#[serde(default)] pub struct SshHostSettings {
    pub alias: String,                  // 必填，连接名
    pub host: String,                   // 必填，主机名/IP
    pub user: Option<String>,
    pub port: Option<u16>,
    pub identity_file: Option<String>,  // 支持 ~
    pub proxy_jump: Option<String>,
    pub extra_args: Vec<String>,        // 仅允许 - 开头，见 build_ssh_argv
}
```

- `SettingsFile` 增加顶层 `ssh: Option<SshSettings>`（与 `plugins` 同款嵌套先例）。
- `TerminalSettings` 增加运行态字段 `ssh: SshSettings` + `Default` 条目（`askpass: true`, `read_ssh_config: true`, `program: Some("ssh")`）。
- `merge_file()` 增加合并分支：`program` 空串归一为 `None`；`port` 限 1..=65535；`extra_args` 过滤空串。
- `default_settings_file()` 增加 `ssh` 示例块。
- 新增 `TerminalSettings::set_ssh_hosts(hosts, cx)`（基于既有 `update()` + 新增 `set_document_ssh_hosts` 补丁 helper，数组整体替换，保留其它键）——为可选的浮层内主机编辑器预留，第一阶段也供设置面板调用。
- 测试：解析、默认值、`patch_settings_file_at_path` 往返且不破坏其它键、非法 port/extra_args 归一。

文档与样例同步：`docs/settings.md` 新增「## Remote SSH」小节、`docs/settings.example.json` 增加 `ssh` 块、`locales/en.json` + `zh_cn.json` 增加键（两个 catalog 必须同步，`i18n.rs` 有测试守着）。

## 6. askpass 助手为什么不新打包一个二进制

`SSH_ASKPASS` 必须是一个可执行文件路径。仓库现成的辅助二进制（`sleipnir-update-helper`）只在 macOS bundle 内分发，Linux/Windows 安装器都不带它，所以新加一个 `sleipnir-askpass` 二进制在发布版里会缺失。

采用：**运行期生成一个 0700 的 shell 脚本** `~/.config/sleipnir/ssh/askpass`，内容为
`#!/bin/sh` + `exec "<current_exe() 绝对路径>" ssh-askpass "$@"`，
由主程序新增隐藏子命令 `ssh-askpass` 完成 socket 往返。零打包改动、三端一致、升级后自动指向新路径（内容变化才重写）。

## 8. 边界情况与降级

| 场景 | 行为 |
|---|---|
| 系统无 `ssh` | PTY spawn 失败，窗格内显示既有 `failed to open PTY: ...` |
| `~/.ssh/config` 不存在/不可读 | `log::warn!`，仅显示应用内主机 |
| `Include` 成环 / 过深 | 深度上限 8 + visited 集合，静默停止 |
| `Host *` 等通配 pattern | 不作为可选主机 |
| `Match` 块 | 整体跳过（保守，不猜条件） |
| OpenSSH < 8.4（无 `SSH_ASKPASS_REQUIRE`） | askpass 不生效，回落到终端内输入；文档说明 |
| Windows | 不设置 `SSH_ASKPASS`，终端内输入；socket 代码编译为桩 |
| 用户取消口令 | `Cancel` → 助手 exit 1 → ssh 自行重试/报错 |
| 窗格在口令pending时被关闭 | `Drop` 停服务、helper 收到 EOF 退出 |
| 助手连不上 socket（app 已退出） | 连接/读超时后 exit 1，不挂死 |
| socket 路径超长（macOS ~104B） | 用 8 字节 hex 短名 + 固定目录，实测 < 70B |
| `extra_args` 被当成远端命令 | 结构上不可能：目标恒为最后一个参数，单测固定 |

安全：socket 目录 0700、socket 0600、脚本 0700；口令只经 socket 与内存传递，不写任何文件、不进日志（日志只记 prompt 文本长度，不记内容）。

## 10. 验证命令

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings   # CI 在 macOS 跑
cargo test --workspace --locked
```

手动冒烟（macOS/Linux，需本机 sshd 或任一可达主机）：
1. `~/.ssh/config` 写一个 `Host smoke-test` → `⌘⇧H` 应列出它，来源显示 `~/.ssh/config`。
2. `settings.json` 加一个 `ssh.hosts` 条目 → 浮层应出现且徽标为 `Sleipnir`。
3. 连接一个需要口令的主机 → 弹出口令模态，输入后登录成功；标签标题显示 alias。
4. 连接一个免密主机 → 无模态直接进 shell；`exit` 后窗格关闭。
5. Esc 取消口令 → ssh 自行失败，不卡死。
6. 删除 `ssh.askpass` 环境场景（设 `ssh.askpass=false`）→ 口令在终端内输入。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| `TermViewEvent` 加变体导致既有 match 非穷尽 | 编译器直接指出，改动局部（`wire_term_view` 等 2~3 处） |
| askpass 在某些 OpenSSH 构建不生效 | `SSH_ASKPASS_REQUIRE=force` + 文档说明最低 8.4；失败可终端内输入 |
| Unix socket 在 CI 沙箱不可用 | 相关测试 `#[cfg(unix)]` 且失败时 `bind()` 返回 None 走降级路径，单测用 tempdir |
| `TermView::new_local_with` 重构影响既有行为 | 仅把 env 构造提取为参数，保持 `new_local`/`new_local_with_cwd` 签名与语义不变，既有测试全绿 |
| 密钥经 socket 被同用户其它进程读取 | 0600 权限 + 每连接一次性 + 5 分钟超时；与 ssh-agent 同等级信任模型 |
